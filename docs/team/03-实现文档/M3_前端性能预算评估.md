|---|---|
| 首页 HTML | ≤ 60 KB |

## 3 结论

| 判断口径 | 结果 |
|---|---|
| 按**未压缩体积** | CSS 超标约 3.3 倍，JS 超标约 2.7 倍 |
| 按**gzip 传输体积** | CSS 39.8–44.4 KB ≤ 80 KB，JS 24.3–25.1 KB ≤ 30 KB，**均达标** |
| HTML | 无论是否压缩均达标 |
| LCP / CLS | 首页 1.5 s / 0，后台看板 1.5 s / 0，均达标 |
| Performance 分数 | 首页与后台看板均为 100 |

因此，“性能预算超标”主要是未压缩体积口径的问题，不是实际传输体积的问题。

## 4 仍存在的性能缺口

| 项 | 现状 | 建议 |
|---|---|---|
| 静态资源缓存 | ✅ 已启用 `Cache-Control: public, max-age=31536000, immutable`（`code/apache-cache.conf`） | 已加入 Dockerfile 并重建验证 |
| HTML 压缩 | ✅ 已确认 `Content-Encoding: gzip`，首页 HTML 传输 3.6 KB | 无需额外配置 |
| PHP 页面缓存 | ✅ 已设置 `Cache-Control: no-store, must-revalidate` | 避免登录态/CSRF 页面被缓存 |
| 图片 | 目前只有 SVG 占位图；真实图片接入后需 WebP/JPEG + 固定宽高比 | 媒体模块上传时处理 |
| ECharts | 尚未加载；接入后只在看板页加载 | 保持按页加载，不放到公共布局 |
| Lighthouse | ✅ 首页/看板 Performance 100，LCP 1.5 s，CLS 0 | 报告 JSON 已留档；演示前可复跑 |

## 5 建议

### 方案 A（已采用）

- 在报告与答辩中明确：性能预算按 **gzip 传输体积** 计。
- ✅ 已新增 `code/apache-cache.conf`：静态资源长缓存、PHP 页面不缓存。
- ✅ `Dockerfile` 已启用 `expires` / `headers` 并载入配置；重建后响应头验证通过。
- ✅ Lighthouse 实测：首页与后台看板 Performance 100，LCP 1.5 s，CLS 0。
- 不改动现有 Bootstrap 结构，避免返工与视觉回归。

### 方案 B（若评审要求按未压缩体积）

1. 用 PurgeCSS 基于现有 PHP 视图生成 Bootstrap 子集（一次性生成，不引入运行时构建链）。
2. 公共页去掉 `bootstrap.bundle.min.js`，用原生 JS 实现移动端导航与资源弹窗。
3. 预计可把公共页 CSS 压到 80 KB 以内、JS 压到 5 KB 以内，但需要 1 天左右做视觉回归。

### 方案 C（不推荐）

完全移除 Bootstrap，改成自写网格与组件。工作量最大，且会推翻现有 25 页的版式基础。

## 6 复测命令

```bash
# 未压缩体积
wc -c code/public/static/vendor/bootstrap/5.3.8/bootstrap.min.css
# gzip 体积
gzip -c code/public/static/vendor/bootstrap/5.3.8/bootstrap.min.css | wc -c
# 响应头
curl -I -H 'Accept-Encoding: gzip' \
  http://localhost:8080/public/static/vendor/bootstrap/5.3.8/bootstrap.min.css
```
